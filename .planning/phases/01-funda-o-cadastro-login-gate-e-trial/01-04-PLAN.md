<objective>
Construir o **gate de acesso** (AUTH-02): uma `GateView` Django leve, GET, read-only, que o Traefik
forwardAuth chama antes de rotear ao Streamlit. Ela resolve `request.user` pelo cookie de sessão
(que o Traefik encaminha), lê a **fonte de verdade** `Conta.status`/`trial_ate` e decide:
**200 + `X-User-Email`** (libera) quando `status=ATIVO` E `trial_ate >= hoje`; **302 → login**
quando anônimo; **302 → /trial-acabou/** quando trial expirado. Inclui a página Django
"seu trial acabou" com [Assinar] placeholder (D-12) e o hardening de cookie em domínio-pai
(`SESSION_COOKIE_DOMAIN`) para o cookie chegar ao gate.

Purpose: AUTH-02 (bloqueio/liberação fail-closed sem vazar o app) e o consumo de `status`/`trial_ate`
como fonte de verdade (BILL-01/ACCT-01). O par Traefik-labels + leitura do header no Streamlit fica
no Plano 05 (repo analista_dividendos). RESEARCH Pattern 1/3.
Output: `apps/gate` com GateView testada por RequestFactory, página trial-acabou, settings de cookie.

REPO ALVO: `~/projects/lazari-capital`. Depende do Plano 02 (semântica ATIVO+trial_ate armada na
verificação). Teste é em ISOLAMENTO (RequestFactory/test client) — o gate ponta-a-ponta com Traefik
+ websockets é escopo da Fase 3.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Traefik (forwardAuth) → GateView | O Traefik encaminha a requisição original (incl. Cookie); o gate é a AUTORIDADE de acesso |
| GateView → Conta (Postgres) | Fonte de verdade read-only; o gate nunca escreve |
| Cookie de sessão do browser → gate | Precisa do domínio-pai para o `sessionid` chegar ao endpoint do gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-17 | Elevation of Privilege | acesso ao app sem sessão válida (bypass de auth) | mitigate | GateView fail-closed: default nega (anônimo/sem conta → 302 login); só `status=ATIVO AND trial_ate>=hoje` retorna 200; teste cobre |
| T-01-18 | Information Disclosure | vazar existência/conteúdo do app ao anônimo | mitigate | Gate responde 302 redirect (não expõe o app) antes de qualquer proxy ao Streamlit; app só é alcançado após 200 |
| T-01-19 | Tampering | trial-date/status tampering para forçar liberação | mitigate | Gate é somente-leitura (nunca muta Conta); `trial_ate` só escrito na verificação (Plano 02); comparação server-side com `timezone.localdate()` |
| T-01-20 | Spoofing | cookie de sessão roubado/hijack | mitigate | `SESSION_COOKIE_SECURE`+`HTTPONLY`+`SameSite=Lax` (prod.py) + HSTS + TLS no Traefik; domínio-pai limita escopo ao site |
| T-01-21 | Denial of Service | loop de redirect (gate ↔ trial-acabou/login) | mitigate | trial-acabou e login são rotas públicas fora do endpoint /gate/ (não recursam pelo gate); RESEARCH Open Q4 |
| T-01-22 | Tampering | CSRF no gate | accept | Gate é GET read-only, sem efeito colateral — CSRF não se aplica; nenhum estado mutável exposto (RESEARCH Anti-Patterns) |
</threat_model>
