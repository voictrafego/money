<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → AssinarView | usuário autenticado envia CPF (input não confiável) |
| backend → Asaas API | criação de customer/subscription; a API key vive no header da Session |
| usuário → checkout | o PAN de cartão NUNCA cruza o backend — só o Asaas hospedado |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering/Input | CpfForm | mitigate | Validar CPF (11 dígitos + dígitos verificadores) na borda do form; rejeitar inválido antes de `criar_cliente` |
| T-02-02 | Info-disclosure | CpfForm/assinar | mitigate | Nunca logar o CPF em claro nem colocá-lo em mensagem de exceção |
| T-02-03 | Info-disclosure/Compliance | assinar.html / AssinarView | mitigate (HIGH) | Checkout hospedado: nenhum campo de cartão no template; redirect 302 ao `invoiceUrl`; backend nunca monta/armazena PAN (D-01) |
| T-02-04 | Elevation/IDOR | AssinarView | mitigate | `conta = request.user.conta`; jamais aceitar conta_id/sub_id do cliente (V4) |
| T-02-05 | Tampering | services.assinar | mitigate | `update_or_create(conta=...)` + UniqueConstraint(conta) → re-assinar não duplica Assinatura (Pitfall 5) |
| T-02-06 | Spoofing | AssinarView | mitigate | `LoginRequiredMixin` — acesso anônimo → 302 login |
| T-02-07 | Info-disclosure | AsaasError na view | mitigate | Não renderizar `str(exc)` cru; AsaasClient já scrub a API key |
</threat_model>
