# Phase 11 — UI Design Contract

> Visual and interaction contract for **Apresentação, hierarquia e trava multi-ticker**.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Surface:** Streamlit (Python). No React, no design system, no component library, no CSS.
The "UI" is built entirely from Streamlit built-in widgets (`st.metric`, `st.dataframe`,
`st.caption`, `st.columns`, `st.tabs`, `st.markdown`). Streamlit owns spacing, typography,
fonts, and base palette — this contract does **not** redefine them. The contract here is
expressed in terms of **widget parameters, formatting rules, labels (pt-BR), metric/delta
presentation, and None/empty states**.

**Invariant (locked, milestone-wide):** `app.py` is **read-only with respect to the method**.
This phase changes only how fields the engine *already exposes* (`dy_recorrente`, `dy_atual`,
`payout(ano)`, `payout_valuation`) are **labeled, formatted, and ordered**. No method
recalculation, no engine change, no golden-valuation rebaseline (D-10).

## Color

**Base palette owned by Streamlit — not declared.** Exactly **one** color decision is in
scope for this phase, and it is a firm design lock:

| Role | Value | Usage |
|------|-------|-------|
| Header trailing-DY delta | `delta_color="off"` (Streamlit neutral gray) | The `st.metric(delta=…)` showing the trailing DY in the header |

**Locked (D-02, Specifics):** The trailing DY delta MUST render **neutral gray** via
`delta_color="off"`. It MUST NOT use the default green/red (`"normal"`) or inverted
(`"inverse"`) coloring. Rationale: trailing DY is typically **higher** than the recurring DY
(it is inflated by extraordinary payouts); a green delta would falsely connote "good" exactly
where the app wants to flag risk. The neutral gray is verified in the live checkpoint (D-08b:
"delta cinza").

No other color is introduced. Inflated-DY signaling reuses the **existing** engine armadilha
alerts (yellow `st.warning` at `app.py:145-147`) — **no new badge/chip** (D-04).

Accent reserved for: not applicable (Streamlit-owned palette; only the `delta_color="off"`
neutralization is specified).

## Formatting Rules (Streamlit-specific contract)

Percentages reuse the **existing** pure helper `fmt_pct(x, casas=1)` (`app.py:51`):
`"—" if x is None else f"{x*100:.1f}%"`. Decimal separator follows `fmt_pct` as-is
(ponto) — **do not** change separators this phase (out of scope, read-only).
None always renders as the em-dash sentinel `"—"` (GRAF-03 None-boundary pattern).

| Field | Source field (engine, already exposed) | Format | Example |
|-------|----------------------------------------|--------|---------|
| Header DY recorrente (primary) | `a.multiplos["DY rec."]` = `c.dy_recorrente()` | `fmt_pct` (%) | `6.3%` |
| Header trailing DY (delta) | `a.multiplos["DY"]` = `c.dy_atual()` | `fmt_pct` (%), prefixed `trailing ` | `trailing 20.3%` |
| Table "DY rec." row | `a.multiplos["DY rec."]` | `fmt_pct` (%) — **bug fix DYR-02** | `6.3%` (today wrongly `0.06` via `fmt_num`) |
| Table "Payout (último ano)" | `c.payout(ult)` **CRU/uncapped** (PAY-02, D-05) | `fmt_pct` (%) | `124.7%` (VULC3) |
| Table "Payout p/ valuation (sustentável)" | `c.payout_valuation()` | `fmt_pct` (%) | `43.1%` (VULC3) |

**DYR-02 fix:** in the Múltiplos row loop (`app.py:324`), add `"DY rec."` to the `%` branch
`("ML","ROE","DY","EY")` so it routes through `fmt_pct` instead of falling into the `fmt_num`
default that produces the `0.06`-style decimal bug.

**PAY-02 fix:** the "Payout (último ano)" row MUST read `c.payout(ult)` (the CRU value the
engine already uses for the armadilha detector at `report.py:156`), **not**
`a.multiplos["DP (payout)"]` (which is `payout_valuation()`). Today both payout rows collapse
to the same clamped value (`app.py:317`); after the fix the two rows are **distinct** numbers.

## Interaction / State Contract

| State | Behavior |
|-------|----------|
| `dy_recorrente` present | Header `m3` shows it as primary (%), trailing as gray delta |
| `dy_recorrente` is None (prejuízo year → normalized earnings undefined) | **Graceful fallback (D-03):** primary = trailing DY (%), explicit "trailing" label, **no delta**, help explains recorrente indisponível |
| `dy_atual` (trailing) is None | delta omitted / `"—"`; primary value still rendered if recorrente present |
| `c.payout(ult)` is None | "Payout (último ano)" → `"—"` |
| `payout_valuation()` is None | "Payout p/ valuation (sustentável)" → `"—"` |
| Armadilha flags (`flag_dy`/`flag_payout`) | Existing yellow `st.warning` alerts unchanged (no new badge — D-04) |

No new toggles, no new tabs, no new buttons. Existing `session_state` flow (`analise_ticker`,
`tec_estado`) is untouched.

## Read-Only Constraint (enforced)

- `app.py` MUST NOT compute or re-derive DY, payout, growth, or any valuation number.
- It MUST only **read** fields already on `a.multiplos` / call `c.payout(ult)` /
  `c.payout_valuation()` (engine methods already invoked elsewhere) and **format/label** them.
- Pure presentation helpers live in **new module `src/analista/report/presentation.py`**
  (D-09), importable **without** starting Streamlit (no import-time side effects). `app.py`
  becomes a thin caller. Helper names/signatures are Claude's discretion.
