<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → LoginView | Credenciais não confiáveis; a sessão emitida governa todo o acesso posterior |
| E-mail (link de reset) → PasswordResetConfirmView | Token de reset é a prova de posse do e-mail para redefinir a senha |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-12 | Spoofing | session fixation no login | mitigate | Django roda `cycle_key()` no `login()` por padrão (não desabilitar); teste de login confirma nova sessão autenticada |
| T-01-13 | Tampering | abuso/replay do token de reset | mitigate | `default_token_generator` (usado pelas views nativas) expira em PASSWORD_RESET_TIMEOUT e invalida ao trocar a senha; token adulterado é recusado |
| T-01-14 | Information Disclosure | enumeração de e-mail no pedido de reset | mitigate | `PasswordResetView` nativa responde idêntico exista ou não o e-mail; teste de anti-enumeração cobre |
| T-01-15 | Elevation of Privilege | login de conta não verificada (is_active=False) | mitigate | Backend padrão do Django recusa autenticação de `is_active=False`; teste cobre |
| T-01-16 | Tampering | CSRF nos POSTs de login/reset | mitigate | `CsrfViewMiddleware` + `{% csrf_token %}` nos templates; em prod `CSRF_TRUSTED_ORIGINS` (Plano 04) |
</threat_model>
